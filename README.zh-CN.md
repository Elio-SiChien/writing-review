# Writing Review · 写作复利

**写批注，先看修改方案，批准后接着审下一稿。**

[English](README.md) · [架构与接口](docs/architecture.md) · [验收](docs/verification.md) · MIT

## 启动

Python 3.10+，无需第三方运行依赖。首次指定Obsidian库：

```sh
python -X utf8 -m writing_review --vault "你的Obsidian库路径"
```

之后Windows可双击 `start.cmd`，浏览器打开 `http://127.0.0.1:8765`。
启动窗口会显示实际数据目录、交接目录和文稿数量；已运行实例与指定配置不一致时会提示先关闭旧窗口，避免打开另一份数据。
不配置库也能保存到私人本机目录；用 `--review-dir` 可指定交接位置。

### 桌面图标（推荐，v0.5）

运行一次，以后双击桌面“写作复利”图标即可（无黑窗；已在运行时只打开页面；日志在 `%LOCALAPPDATA%\WritingReview\server.log`）：

```powershell
powershell -ExecutionPolicy Bypass -File install_shortcut.ps1 -Vault "你的Obsidian库路径"
```

### 由AI直接推送LaTeX稿件（v0.5）

AI写完一节后运行，稿件直接出现在工具里：段落带小节号，数字宏已替换，每张图是一张可批注的图卡片（图片 + 图注）。

```sh
python -X utf8 tools/push_latex.py --latex-dir <含main.tex的目录> --sections results.tex --title "论文2_结果_第1轮" --figures-dir <PNG图片目录>
```

先编译LaTeX（需要 main.aux 解析图号、小节号和引用编号）。正文没变时重复推送不会新建文稿；正文变了会生成新文稿，不覆盖旧的。

### 拖入PDF（v0.5）

把PDF拖到页面任意位置（或点“打开文稿”选择PDF），本机服务自动转成段落，出现在文稿下拉列表里，可以像其他文稿一样批注。适合别人发来的PDF或Word导出的PDF。

- 每段标注页码（如 `p.3`，跨页为 `p.3-4`），原PDF另存一份在数据目录 `assets/<文稿ID>/original.pdf`，交接Markdown里写明原件路径。
- 按双栏版面顺序读（先左栏后右栏，通栏标题和大图会分隔版面）；去掉每页重复的页眉页脚、页码和审稿稿行号；行末连字符断开的英文单词会接回。
- 同一个PDF再次拖入只会打开已有文稿，不会重复建稿。
- 扫描件（没有文字层）会提示“不支持扫描件”，请先OCR或导出TXT/Markdown。
- 需要 PyMuPDF：`pip install pymupdf`（只有这个功能需要，未安装时页面会给出中文提示）。转换是启发式的，复杂版面（公式、表格、脚注）可能分段不准，批注前请快速浏览一遍。

## 只需三个步骤

1. **打开文稿**：打开或拖入PDF、TXT、Markdown或已有备份，选择场景。项目归属自动继承或生成，不用填写ID。
2. **添加批注**：选中句子后添加意见，不选文字则批注整段。点击保存立即写入；有批注的位置显示黄色。右侧最新意见在上方，编辑旧意见保留创建时间并显示“已编辑”。
3. **请AI出修改方案**：按钮复制指令，粘贴到当前AI聊天。AI先给逐条方案和拟沉淀偏好，你批准后再改稿、整理偏好并建立下一轮。页面不会假装已调用AI。

新一轮准备好后，页面在没有未发送修改或打开的草稿时自动切换。旧轮次保留、只读；已处理意见留在旧稿，未处理的可带入新稿。文稿保存版本和修订轮次分开，不需要记技术编号。

## 语音批注

点击批注输入框，按 **Win＋H** 使用Windows语音输入，检查识别文字后保存。此功能由系统提供，需要可用麦克风和联网；工具只保存文字。也可继续键盘输入，无需模型账号或网页录音按钮。

## 保存与恢复

保存批注时立即写数据库和配置的交接目录，完整成功后，目录位于库内才显示“已保存到Obsidian”，否则显示“已保存到本机”。目录暂时不可写时，本机副本保留并自动重试。浏览器保留未发送内容和输入草稿；新稿不会悄悄覆盖旧标签中的修改。

“保存位置与备份”收起显示详细目录及下载备份入口。重试和恢复按钮仅在需要时出现。原离线页面、旧JSON兼容性保留；纯离线页面不能自动写入固定目录，需要下载备份交回。

配置库后的默认目录为 `写作复利/批注收件箱/`。v0.5起每份文稿目录只有三个文件（新文稿目录名可读，如 `20261119_论文2_讨论_第1轮`；旧文稿保留原编号目录名，路径不变）：

- `CURRENT.json`：当前保存版本的指针，`review` 字段内含完整结构化记录（原稿、当前正文、选文锚点、批注），`files.markdown` 指向当前Markdown及其校验值。AI先读它。
- `ROUND.json`：同一文稿的稳定身份、轮次和上下稿关系。
- `latest.md`：方便通读的当前稿与批注。

加批注、改批注不再生成整篇快照；只有正文改变或建立新一轮时，才在本机数据库（SQLite `history` 表）里存一个文字版本。Obsidian里不再写 `history/`。旧目录里遗留的 `history/`、`latest.json` 不是最新依据，可用下面的清理脚本归档。导出保护：不会写进属于其他文稿的目录，不会把较新的版本回退，同一版本号内容不同时拒绝覆盖。

AI执行前必须再次核对批准的源版本；有新意见先补充方案。没有本地文件权限的AI，由你提供备份文件。保存成功不代表AI已经处理或学习。

## 清理旧冗余（v0.5）

`tools/cleanup_redundancy.py` 默认只空跑：只读扫描交接目录和数据库，列出可清理的项目和大小，写成报告 `docs/清理清单_dryrun_<日期>.md`，不改任何文件。

```sh
python -X utf8 tools/cleanup_redundancy.py            # 空跑，只出清单
python -X utf8 tools/cleanup_redundancy.py --execute  # 确认清单后才运行
```

清单分四类：没有被 CURRENT.json 指向的旧历史快照、内容相同（只差版本号）的重复快照、CURRENT.json 已内含记录的旧 `latest.json`、数据库里没有对应文稿的孤立目录。`--execute` 会先把整个交接目录完整备份到库外 `writing-review-backups/` 并核对文件数，再把清单中的项目写入库外zip归档并逐个校验，校验通过后才从库中移走；服务运行时默认拒绝执行。数据库不改。

## 写作复利

AI先读风格速查及对应场景规则，批准后再记录明确偏好、来源和修改前后例子。推断只进入候选；保留人工正文和冲突历史。本篇术语不自动升级为所有项目的规则。

默认不调用后台模型。旧 `--auto-extract` 适配器仅为主动开启的高级选项，现在只生成待批准方案，不自动激活偏好。它需要兼容模型与登录，启用时会发送相关编辑材料给所配置提供方。当前聊天审批流程不依赖此适配器。

工具只监听本机127.0.0.1，不能验证外部聊天的真实批准；执行AI须遵守用户授权。真实稿件、批注和Obsidian库不要加入公开仓库。测试与接口见English说明。

## 三类场景

只保留学术写作、基金写作、通用。新文稿默认通用；旧引言和摘要显示学术写作，旧报告归通用。
不增加子场景或配置；已有引言等专属偏好保留适用条件，不扩大到整个学术写作。历史稿与批注不重写。
默认交付普通正文、处理记录和下一轮审阅，不额外生成排版文件。
