# Writing Review · 写作复利

**写批注，先看修改方案，批准后接着审下一稿。**

[English](README.md) · [架构与接口](docs/architecture.md) · [验收](docs/verification.md) · MIT

## 启动

Python 3.10+，无需第三方运行依赖。首次指定Obsidian库：

```sh
python -X utf8 -m writing_review --vault "你的Obsidian库路径"
```

之后Windows可双击 `start.cmd`，浏览器打开 `http://127.0.0.1:8765`。
不配置库也能保存到私人本机目录；用 `--review-dir` 可指定交接位置。

## 只需三个步骤

1. **打开文稿**：打开TXT、Markdown或已有备份，选择场景。项目归属自动继承或生成，不用填写ID。
2. **添加批注**：选中句子后添加意见，不选文字则批注整段。点击保存立即写入；有批注的位置显示黄色。右侧最新意见在上方，编辑旧意见保留创建时间并显示“已编辑”。
3. **请AI出修改方案**：按钮复制指令，粘贴到当前AI聊天。AI先给逐条方案和拟沉淀偏好，你批准后再改稿、整理偏好并建立下一轮。页面不会假装已调用AI。

新一轮准备好后，页面在没有未发送修改或打开的草稿时自动切换。旧轮次保留、只读；已处理意见留在旧稿，未处理的可带入新稿。文稿保存版本和修订轮次分开，不需要记技术编号。

## 保存与恢复

保存批注时立即写数据库和配置的交接目录，完整成功后，目录位于库内才显示“已保存到Obsidian”，否则显示“已保存到本机”。目录暂时不可写时，本机副本保留并自动重试。浏览器保留未发送内容和输入草稿；新稿不会悄悄覆盖旧标签中的修改。

“保存位置与备份”收起显示详细目录及下载备份入口。重试和恢复按钮仅在需要时出现。原离线页面、旧JSON兼容性保留；纯离线页面不能自动写入固定目录，需要下载备份交回。

配置库后的默认目录为 `写作复利/批注收件箱/`。每份审阅记录有：

- `CURRENT.json`：指向已完整保存的版本JSON与Markdown，AI先读它。
- `ROUND.json`：同一文稿的稳定身份、轮次和上下稿关系。
- `latest.json`、`latest.md`：方便阅读的当前副本。
- `history/`：旧保存版本，不覆盖。

AI执行前必须再次核对批准的源版本；有新意见先补充方案。没有本地文件权限的AI，由你提供备份文件。保存成功不代表AI已经处理或学习。

## 写作复利

AI先读风格速查及对应场景规则，批准后再记录明确偏好、来源和修改前后例子。推断只进入候选；保留人工正文和冲突历史。本篇术语不自动升级为所有项目的规则。

默认不调用后台模型。旧 `--auto-extract` 适配器仅为主动开启的高级选项，现在只生成待批准方案，不自动激活偏好。它需要兼容模型与登录，启用时会发送相关编辑材料给所配置提供方。当前聊天审批流程不依赖此适配器。

工具只监听本机127.0.0.1，不能验证外部聊天的真实批准；执行AI须遵守用户授权。真实稿件、批注和Obsidian库不要加入公开仓库。测试与接口见English说明。

## 三类场景

只保留学术写作、基金写作、通用。新文稿默认通用；旧引言和摘要显示学术写作，旧报告归通用。
不增加子场景或配置；已有引言等专属偏好保留适用条件，不扩大到整个学术写作。历史稿与批注不重写。
默认交付普通正文、处理记录和下一轮审阅，不额外生成排版文件。
